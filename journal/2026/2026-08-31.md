## Ceph Network Routing Correction

Corrected the dedicated Ceph interfaces on the Proxmox nodes to use the actual `10.10.10.0/24` storage subnet rather than an overly broad `/8` mask. The Ceph-facing configuration is maintained under `/etc/network/interfaces.d/ceph`.

With `/8`, Linux considered unrelated `10.x.x.x` destinations directly reachable through the Ceph interface. That made route selection ambiguous and could send traffic through the storage-facing interface when it belonged on the normal front network. The problem was therefore not merely cosmetic subnet notation: the interface mask was influencing which physical path the hosts selected.

Restricting the Ceph interfaces to `/24` made the routing intent explicit. Traffic for `10.10.10.x` remained directly connected to the dedicated 10GbE storage fabric, while other `10.x` networks used the normal routed/front-side path. Ceph configuration was aligned around the same `10.10.10.0/24` network.

## Result

Ceph hosts selected their dedicated `10.10.10.x` addresses and 10GbE interfaces for storage communication instead of allowing traffic to fall back through or interfere with the front network.

Observed transfer performance improved from roughly 180 Mbps to approximately 418 Mbps during the network correction work. The change also left the routing table substantially easier to reason about: the storage interface owns only the storage Layer-2 subnet rather than effectively claiming all RFC1918 `10/8` destinations.
