## RAG and Librarian Pipeline

Brought the shared PostgreSQL/pgvector RAG system and Librarian ingestion path to an operational state and validated it with a real source. The data model was standardized as collection → source → document → chunk + embedding, with provenance retained alongside searchable content.

Database authority was separated into `rag_reader` and `rag_writer` capabilities. Hermes exposed corresponding read-only `rag` and custodial `rag_write` toolsets, while the Librarian became the narrow authority responsible for source custody, classification, ingestion, and knowledge curation. Other agents could propose or retrieve material without receiving direct authority to populate the canonical corpus.

A dedicated CPU embedding service was deployed using `BAAI/bge-base-en-v1.5` with 768-dimensional vectors. The first ingestion failure exposed a mismatch between character-based chunking and the embedding model's token limit. The worker was changed to use the model tokenizer with a 500-token chunk size and 50-token overlap.

## Verification

A real arXiv-derived source was preserved, corrected when its `.pdf` representation proved misleading, classified, ingested into 13 chunks, embedded, and retrieved semantically as the top result at roughly 0.774 similarity.

Knowledge boundaries were also clarified: RAG holds source evidence; the LLM Wiki holds established organizational knowledge; Supermemory holds durable contextual memory; project files hold working state/artifacts; Kanban holds execution state.

## Result

The knowledge system moved from architecture to a tested ingestion/retrieval pipeline. Long-running objectives could now be decomposed into bounded fresh-agent sessions while evidence and project state persisted outside any individual context window.
