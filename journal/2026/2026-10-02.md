# 2026-10-02

`cephfs` `kubernetes` `mysql` `web`

## Context

Healthboard was still primarily a PHP application focused on labwork backed by a small MySQL schema. Work began on a separate `health-v2` tree to develop it into a broader health record without disrupting the existing `/health` application.

The homelab copy also had not previously been fully exercised as a local PHP site, only the VPS. Kubernetes was serving the shared CephFS web tree through nginx and PHP-FPM, but website was not routed through the local Cilium ingress and the application retained VPS-specific filesystem assumptions.

## Changes

Defined the Healthboard v2 architecture around events, clinical records, treatments, nutrition and longitudinal measurements. MySQL remains authoritative for structured and sparse records while InfluxDB holds repeated numeric observations. Source/provenance identity is retained so measurements from devices, imports and manual entry remain distinguishable.

Created three additive schema migrations and exercised them against `ai-sandbox`, preserving the existing production lab schema. The v2 application gained event/timeline, treatments, profile, measurements and nutrition views while retaining the original labs interface and `/health` as the rollback path.

Added the project's URL to the homelab nginx/Cilium HTTP and TLS routing. HTTPS successfully reached nginx, PHP-FPM and the CephFS-hosted application. This exposed hard-coded VPS path assumptions; v2 filesystem resolution was changed to support both VPS and homelab layouts.

The stock Kubernetes PHP image lacked `mysqli` and `pdo_mysql`. The existing image was used as a base and a new was built with the required MySQL extensions.

USDA FoodData Central and associated databases were selected as the nutrition catalog source. A full CSV importer was implemented and tested in `ai-sandbox`, mirroring all 34 source tables and approximately 36 million rows while keeping personal foods separate from vendor catalog data.

Google Health Takeout ingestion was then added using the extracted archive as an immutable source. Reusable import tooling catalogs source artifacts, tracks files by SHA-256 and writes observations idempotently with stable source/origin identity. At the session checkpoint, 14,737 files had been cataloged and roughly 41.9 million unique observations imported into InfluxDB, with structured sleep, exercise, nutrition, weight and related records staged in MySQL.

Import work also established explicit time semantics for legacy data rather than applying a blanket timezone. Source timestamps and inferred timezone provenance are retained, while date-only records use local noon solely as a storage/query anchor without presenting an invented time. Measurement views can distinguish Takeout provider data by originating device or application and bucket dense series for practical chart rendering.

The Takeout import remains incomplete: 3,163 health files still require coverage review, primarily older dense JSON overlapping newer CSV sources. Changed files that remove previously imported observations also require a future reconciliation mechanism.

## Result

Healthboard v2 now has a sandboxed architecture, working homelab execution path, large USDA nutrition catalog and substantial historical Google Health dataset without changing production data. The local site can be reached through the normal hostname and TLS path, and the application is no longer tied to the VPS filesystem layout.

V2 remains development-only. Clinical uploads still require writable persistent private storage, Google OAuth has not been live-tested, production placement of the USDA catalog remains undecided, and broader workflow and Takeout coverage testing remain before migration.
