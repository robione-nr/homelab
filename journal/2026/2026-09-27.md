## Utility Server Migration

Moved the VPS Utility Server from its older project path into `/var/www/common-assets/python/utility-server`. The FastAPI/Uvicorn service continued to provide shared UUID, heartbeat, token, and TOTP functions for web applications and administrative authentication.

The systemd unit initially retained assumptions about the previous virtual-environment location. After correcting the execution path, the service ran under `www-data`, used the new working directory, remained bound to `127.0.0.1:8037`, and retained its hardening options.

## Scheduled Maintenance

Watchdog and cleanup scheduling were reviewed as part of the migration. Stale cron entries still referenced the previous path, and a root crontab entry had been written using `/etc/cron.d` syntax, producing `/bin/sh: 1: root: not found`.

## Result

The Utility Server itself returned to a healthy running state under the consolidated common-assets layout. The migration also exposed why service moves must include systemd, virtual environments, watchdogs, and cron consumers—not just the application files.
