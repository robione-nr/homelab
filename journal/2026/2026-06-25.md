## HA and Storage Architecture

Refined the target Proxmox/Ceph architecture around shared storage and multiple virtualization hosts. Stateful services such as email could not gain meaningful VM failover merely by having another Proxmox node available; their storage also needed to survive loss of the original host.

Ceph was therefore evaluated as part of the HA design rather than as a standalone storage project. Proxmox Backup Server remained conceptually separate from the Ceph cluster it protects so a cluster failure would not automatically remove the recovery path.

Resource planning also changed. Host memory and CPU could not be allocated almost entirely to Kubernetes guests: Proxmox, filesystem caching, Ceph daemons, and recovery operations needed explicit headroom.

## Result

The architecture separated three different concerns that are easy to conflate: service availability, shared/replicated storage, and backup. Ceph could support failover, but it was not itself the backup system; additional Proxmox nodes could host workloads, but they did not make state portable without appropriate storage.

That distinction guided the later three-node Proxmox/Ceph design.
