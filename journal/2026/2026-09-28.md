## xsrv-api Security Boundary

Established `xsrv-api` as the controlled interface for agent access to CephFS-backed web projects and managed application databases. The goal was to stop equating filesystem/database availability with unrestricted agent authority.

Filesystem operations were scoped to configured roots. Requests outside those roots were rejected rather than relying on agents to remember which host paths were safe. The same principle applied to databases: agents should discover schemas and use authorized API operations instead of connecting directly with broad credentials.

## Development Boundary

Schema experimentation and destructive work were directed toward disposable or sandbox state. Production DDL and unrestricted managed-database access remained outside normal agent authority unless explicitly authorized.

## Result

`xsrv-api` became an enforcement point rather than merely a convenience wrapper. This allowed CephFS and database resources to remain broadly useful to automation while preserving a narrow, reviewable interface for mutations.

The architecture also reduced the significance of matching Unix UIDs alone: filesystem permissions could permit a process to reach data without implying that an autonomous agent should bypass the API boundary.
