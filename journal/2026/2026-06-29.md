## Second Proxmox Node

Started integrating the Supermicro SYS-1028GQ-TXR into the Proxmox environment alongside the Dell R630 infrastructure. The work covered cluster membership, Tailscale management, Ceph client access, Kubernetes VM placement, and planning for GPU passthrough.

The Supermicro's four Tesla P100 SXM2 GPUs made it materially different from the general-purpose nodes, but joining it to Proxmox provided consistent lifecycle management and access to shared infrastructure.

A two-node cluster limitation was explicitly recognized: two voting nodes do not provide robust quorum behavior by themselves. A third node or QDevice would be required before treating the Proxmox cluster as genuinely highly available.

## Result

The system moved from a single virtualization host plus specialized hardware toward a cluster architecture, while avoiding the assumption that “clustered” automatically meant “HA.” Storage, quorum, network redundancy, and workload placement still had to be solved independently.
