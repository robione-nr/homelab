## Synchronization Validation

Continued validating the consolidated Unison service from `svc-utility`. Simple file modifications synchronized successfully from VPS to homelab and from homelab to VPS, confirming that SSH transport, permissions, roots, and the basic Unison profile were functioning.

The remaining uncertainty centered on editor behavior. Nano may save through temporary/swap/rename patterns rather than producing the same filesystem event as a simple append or overwrite. Those changes were not always observed as promptly as direct test writes, making “eventually consistent after a rescan” insufficient evidence that the watch configuration was healthy.

## Artifact Handling

Swap and temporary files were explicitly excluded so `.swp`, `.tmp`, and Unison working artifacts would not become normal project content. Existing artifacts were treated as evidence to investigate rather than files that should be synchronized.

## Result

The synchronization system was operational but not yet trusted enough to declare validation complete. Retirement of the older `svc-sync` container remained contingent on proving that normal editing workflows reliably trigger propagation, not merely that synthetic file changes can cross the link.
