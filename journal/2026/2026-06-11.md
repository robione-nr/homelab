## Repository Reorganization

Began reorganizing infrastructure and application work into project-oriented Git repositories. The previous working layout mixed operational files, documentation, and application content too freely to serve as a durable public record.

The emerging model separated public documentation and sanitized examples from private operational repositories containing production application code, VPS configuration, mail configuration, credentials references, and deployment material. Repository boundaries were chosen around projects and operational ownership rather than around file type alone.

## Result

GitHub became both the change-history layer and the public documentation surface for the homelab. Sensitive production state could remain private while architecture, lessons learned, and reusable configuration patterns could be documented publicly.

This also created the need for a journal that records decisions and resulting state without copying secrets, raw transcripts, or every troubleshooting command into the repository.
