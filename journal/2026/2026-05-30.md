## Utility Server and Service Foundation

Expanded the Python 3.11 multi-domain Utility Server used by VPS-hosted applications. Its responsibilities included reusable functions such as token handling and TOTP verification, with rate limiting and MySQL-backed state added as the service became shared infrastructure rather than project-specific code.

Redis was evaluated for state that was ephemeral or operational rather than relational. In parallel, application data responsibilities were being separated across MySQL/PostgreSQL, ArangoDB, Redis, and API services instead of allowing each web project to create its own isolated implementation.

## Architectural Effect

The Utility Server became an early example of extracting common capabilities from individual websites and hosting them once behind a local service interface. This reduced duplicated authentication/security logic and created a recognizable shared-services layer on the VPS.

The same service-oriented approach later appeared in the homelab as datastore APIs, embedding services, `xsrv-api`, and other narrowly scoped internal endpoints.
