## Network Migration Strategy

Worked through migration from the original `192.168.1.x` environment toward structured `10.x` networks while preserving a dedicated Ceph network. The target topology included three Proxmox nodes, Ceph OSDs, redundant DNS and HAProxy/Keepalived services, and a Kubernetes cluster with three control planes plus workers.

The desired end state was substantially more redundant than the network available at the time, but remote administration imposed an important constraint: an addressing, VLAN, or switching mistake could remove the only practical management path.

## Decision

The migration would be incremental. A conservative temporary network was preferable to implementing MLAG, VLAN segmentation, and address changes simultaneously while remote. More disruptive physical-switch changes could wait until onsite console access was available.

This established a recurring approach for the homelab: design toward the final architecture, but sequence changes so that recoverability is preserved at every intermediate state.
