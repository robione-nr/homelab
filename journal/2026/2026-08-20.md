## Agent Routing and Secret Boundaries

Added an agent directory alongside the core Hermes documentation to separate role/capability discovery from individual agent prompts. Delegation could then be based on explicit responsibilities rather than embedding an ever-growing routing table into every agent.

Datastore access was traced to the Kubernetes `datastore-api` service, reinforcing the decision to put controlled service interfaces between agents and managed databases.

Secret-handling rules were made explicit: authorized credentials may be consumed from the runtime environment when required, but agents must not print, log, commit, persist, or disclose their values. Configuration that described the environment continued moving out of conversational prompts and into durable configuration files.

## Result

The agent system gained clearer boundaries between identity, routing, tools, configuration, and secrets. This reduced prompt bloat and made permissions easier to reason about as the number of agents and backend services increased.
