## VPS Project Layout

Standardized VPS-hosted projects around `/var/www/<project>/`, separating public web content from application code, scripts, configuration, and documentation. Apache `DocumentRoot` would expose only the intended public subtree rather than the repository/project root.

The same principle was applied to mail infrastructure documentation. Production Postfix/Dovecot configuration and operational details could remain private while sanitized documentation captured DNS authentication, TLS, monitoring, security, and deployment architecture.

## Why It Mattered

The layout reduced accidental exposure risk and made projects easier to synchronize, version, and reason about. A repository could contain everything required to understand or operate a project without implying that every repository file belonged under the web server's public document root.

This project structure later became important when CephFS and Unison were introduced. Host-specific files could be excluded while the shared project tree retained a predictable organization across VPS, homelab, and development environments.
