## Resource Gateway and Utility Consolidation

Formalized CephFS as authoritative web-project storage and consolidated controlled access around `svc-utility` (CT 1500, `10.0.1.8`). `xsrv-api` on port `8040` became the authenticated gateway for scoped filesystem and managed-database operations rather than giving development agents unrestricted host or database credentials.

The ownership target was physical `1000:1000` for development content and `0:0` for infrastructure-managed content. The original unprivileged LXC mapping translated container identities into the `100000+` range, and custom mappings made root-owned infrastructure content awkward.

## Privileged LXC Conversion

For this trusted infrastructure container, `svc-utility` was converted to a privileged LXC so container root maps directly to physical `0:0` and container `admin` maps directly to `1000:1000`. The conversion was proven by backing up the correctly mapped unprivileged container and restoring it as privileged; simply toggling the LXC mode was rejected because the existing root filesystem contained shifted ownership.

The security tradeoff was explicit: privileged LXC isolation is weaker, so application services such as `xsrv-api` continue to run as `admin`, reserving root for infrastructure administration.

## Unison Consolidation

Unison synchronization was also consolidated into `svc-utility`, using `/mnt` ↔ VPS `/var/www` over SSH. Direct bidirectional changes worked, but CephFS writes performed by other clients do not necessarily generate local inotify events inside CT 1500. Continuous synchronization therefore still required validation/event signaling before the older `svc-sync` container could be retired confidently.

## Result

CephFS ownership, controlled agent access, database authorization, Certbot-related access, and project synchronization converged around one utility-service boundary without equating filesystem permission with autonomous-agent authority.
