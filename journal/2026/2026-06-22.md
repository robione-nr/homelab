## Mail Architecture Documentation

Documented the self-hosted mail stack built around Postfix, Dovecot, OpenDKIM, OpenDMARC, and SpamAssassin. SPF, DKIM, and DMARC DNS records were already part of the deployment, making DNS configuration an operational dependency of the mail system rather than merely domain administration.

The documentation treated mail as a complete service with database dependencies, TLS, storage, authentication, monitoring, deliverability, and recovery concerns. Production configuration remained distinct from sanitized public documentation so the architecture could be shared without publishing sensitive operational state.

## Result

Email became a first-class workload in the same infrastructure record as web hosting, databases, and AI. This was important because later changes to storage, database replication, DNS, VPS connectivity, or failover could affect mail even when the work was not initiated as an “email project.”

The journal therefore includes meaningful email changes whenever they alter or depend on the infrastructure, rather than treating mail as an unrelated VPS service.
